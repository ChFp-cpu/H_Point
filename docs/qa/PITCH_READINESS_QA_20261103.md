# Подготовка H-Point к пилоту и демонстрации

## Реализовано

- Публичная услуга → email-вход с сохранением введённых полей → приватное
  обращение с тремя фото → входящие организации → ответ/сотрудник → клиент и
  запись. Переносятся контакт, описание, название, цена и длительность.
- Автор видит ответ и запись в профиле и может отменить открытое обращение.
  Создание обращения и записи не выполняет денежных операций.
- Руководители видят входящие организации, сотрудник — назначенные обращения.
  Уход/удаление сотрудника снимает назначение. После окончания доступа
  сохраняется чтение, рабочие изменения требуют действующего доступа.
- Повторы отправки и конвертации не создают дубликатов; создание клиента и
  записи атомарно, проверяются пересечения и принадлежность организации.
- Фото доступны только участникам обращения, сервер удаляет метаданные и
  перекодирует изображения; приватные ответы имеют no-store.
- На главной — число открытых рабочих обращений и переход во входящие;
  в новом кабинете — короткие первые шаги. Каталог имеет прямую кнопку обращения.
- Административная воронка регистрации, помощи, услуг, обращений, повторного
  использования и D7. Старые аккаунты по умолчанию без классификации;
  группы pilot/demo/real назначает администратор. Фоновый опрос не считается
  активностью, незрелый седьмой день не входит в знаменатель D7.
- Изолированное локальное демо с вымышленными email-аккаунтами и заметным
  баннером, без запуска бота/внешней почты/платежей. Защита от production URL,
  новая база при каждом запуске, исключение данных из Git и Docker-контекста.

## Найденные и исправленные регрессии

1. Глобальная legacy-функция history затеняла браузерный History API.
2. Новые JS отсутствовали в allowlist статических файлов.
3. Чтение фото через blob URL блокировалось CSP: используется FileReader,
   без расширения политики безопасности.
4. Ошибка ответа стиралась финальной перерисовкой, сохранялся лишний loader,
   счётчик входящих расходился с фактическими данными.
5. При продлении PRO перерисовка создавала активную кнопку до завершения
   покупки. Введена блокировка по аккаунту на весь процесс и защита от
   устаревших billing-ответов. Старые ответы не откатывают оплаченный срок.

## Локальная проверка

Полный Python-прогон: **757 тестов, 545 пройдено, 212 PostgreSQL-проверок
пропущено без отдельной БД**. После финальной правки покупки дополнительно
пройдены 37 тестов web. PostgreSQL-наборы новых модулей добавлены в CI.

Новые сценарии:

- inquiries_browser — 63 проверки;
- pilot_browser — 41;
- public_organization_visual_browser — 61;
- personal_browser — 196, включая задержанные реальные billing-ответы,
  повторные нажатия после перерисовки и ровно два ожидаемых списания;
- subscriptions_browser — 98.

Также прошли startup, mobile_home, mobile_support, header_stability,
password_recovery, registration_directions, chat_scroll, chat_autofill,
marketplace_chat, work_estimates, work_modern, admin_support и services_visual.
Это 18 различных браузерных сценариев с учётом перечисленных выше.
Ошибок JavaScript в успешных прогонах нет. Фото, ошибки/повторы, роли,
история браузера, отсутствие списаний и дубликатов проверены реальными API
на временных локальных базах. Светлая/тёмная темы и ширины 320–1440 px
проверены; новые экраны обращений и аналитики просмотрены по скриншотам.

Демо дополнительно проверено отдельным HTTP-процессом: запуск, health,
email-login, регистрация и локальный код, страницы организации, входящие,
demo=5/real=0. Процесс остановлен, порт закрыт.

## Границы результата

Рабочая база не используется для синтетических регистраций и покупок.
Деньги остаются тестовыми; группы аккаунтов не присваиваются массово.
Обращения видны на сайте, отдельная доставка этих обращений в Telegram
не добавлена. Просмотры услуг охватывают только вошедших пользователей.
Повторное использование кабинета оценивается по датам сохранённых записей;
удаления могут уменьшить исторические показатели.

Реальные интервью, привлечение пилота и подтверждение готовности платить
остаются работой команды. Инструкция и демонстрация: [PITCH_RUNBOOK.md](../demo/PITCH_RUNBOOK.md).
