# Аудит H-Point перед демонстрацией

Дата: 4 ноября 2026 года. Проверена версия на основе `a8f0ba7` и исправления
этого аудита. Цель — устранить воспроизводимые дефекты, сохранить действующие
сценарии и подготовить показ. Абсолютное отсутствие ошибок или качество любого
исполнителя тестами гарантировать нельзя.

## Обязательные исправления и результат

| Проблема | Сделано | Проверка |
|---|---|---|
| Сотрудник получал внутреннюю себестоимость и прибыль сметы через API | Эти поля удалены из DTO сотрудника и отчётов; руководитель сохраняет доступ | SQLite/PostgreSQL regression и браузер команды |
| Новая запись могла ссылаться на архивного клиента/услугу | Сервер отклоняет новые архивные ссылки; редактирование прежних исторических записей сохраняется | Unit/API, создание и редактирование записи в браузере |
| Старая вкладка принимала истёкшую заявку до фонового закрытия | Актуальность проверяется внутри блокировки при отклике, выборе и принятии приглашения | Новые lifecycle tests, PostgreSQL ожидание row lock с переходом срока |
| Дробные/логические оценки превращались в целые | Допускаются только JSON-целые 1–5, проверка повторена в сервисе | HTTP и бизнес-логика обеих сторон |
| Неверная структура JSON/полей вызывала HTTP 500 | Общий object guard, проверка категорий/повторов/ID и переполнения дат | Все семейства POST, malformed personal data, отсутствие побочных записей |
| Задержанный вход/регистрация/подтверждение меняли новую форму | Проверяется исходная форма, окно и аккаунт до обработки ответа | 18 браузерных проверок с настоящими задержанными ответами |
| Старый ответ профиля открывался после закрытия или смены пользователя | Профильные запросы привязаны к актуальному контексту | Закрытие, замена окна, другой аккаунт, параллельные профили |
| Старый список активностей и чтение фото перезаписывали новый черновик | Серийность загрузок, проверка формы/аккаунта, блокировка публикации во время чтения, один POST | 22 браузерные проверки, включая отсутствие переноса фото между черновиками |
| Истёкший текущий рабочий профиль назывался прежним | Исправлена подпись и подсказка о доступных клиентах | Браузер смет и рабочего кабинета |
| После сохранения ответа форма входящих показывала старые значения | Серверный результат обновляет карточку до повторного захвата черновиков; поля заблокированы на время сохранения | Сохранённые текст/статус, ручное обновление, ошибка и повторная отправка |
| Поддержка хранила только последний ответ и была неудобна для переписки | Добавлены история сообщений, статусы, поиск, фильтры, непрочитанные, постраничная загрузка и защита от повторной отправки | Бизнес-логика, HTTP, браузер пользователя и администратора |
| Панель администратора находилась в профиле | Отдельная страница в главном меню после активностей, только для администратора; прежнее управление сообществом сохранено | Ролевой доступ, навигация и адаптивность |
| Ручные заявки проверки личности больше не нужны | Новые заявки отключены в сайте и боте, исторические записи сохранены | HTTP 410 и no-op старых команд без изменения базы |
| Основные данные профиля редактировались неочевидно | Постоянная форма, сохранение/отмена, проверка полей, стабильный черновик и ошибки без потери текста | HTTP и 31 браузерная проверка |
| Отвязка Telegram могла использовать совпавший старый числовой ID | Проверяется именно текущая привязка отправителя | Канонический пользователь, чужая и отменённая привязка |
| Отзыв фотографией вызывал ошибку, а завершённые записи вытесняли напоминания | Проверка текстового отзыва с сохранением состояния; фильтр актуальных записей применяется до LIMIT | FakeBot и отдельный PostgreSQL-прогон |
| Регулярные копии и восстановление не были оформлены как проверяемая процедура | После явного разрешения включены почасовые копии на 14 дней и проверено восстановление отдельной копии | Linux mock tests и реальное восстановление в изолированный временный PostgreSQL; рабочая база не заменялась |

## Результаты воспроизводимых проверок

- После доработки поддержки и профиля: **837 Python-тестов**, **587 успешно**,
  **250 пропущено** для отдельных PostgreSQL/Linux-прогонов. Для нового центра
  поддержки дополнительно проверены приватность, гонки, реальные HTTP-маршруты,
  переписка, статусы и миграция старых ответов.
- Повторно проверен весь набор из **55 браузерных сценариев — все успешно**.
  Ожидания старого меню и скрытого редактора приведены к новой навигации;
  затронутые сценарии повторно прошли после исправлений. Детали поддержки, профиля и
  бота: [SUPPORT_PROFILE_QA_20261104.md](SUPPORT_PROFILE_QA_20261104.md).
- Полный локальный Python-прогон: **786 тестов**, **558 успешно**,
  **228 пропущено**: PostgreSQL и POSIX-проверки выполняются в отдельном Linux CI.
- Первый полный браузерный прогон: 51 сценарий, 49 успешных. Два падения
  устранены в проверках: устаревший текст закрытого Games и наличие второго
  активного клиента в фикстуре.
- Финальный прогон затронутых областей: **9 из 9 успешно**. В него вошли
  исправленные сценарии и два новых. Всего успешно проверено **53 разных
  браузерных сценария** с учётом последних версий.
- Новые проверки контекста входа: 18; контекста активностей: 22.
- После визуальной репетиции повторно проверены входящие: 74 проверки,
  включая сохранение текста/статуса и черновика после ошибки.
- Сметы: 122 браузерные проверки и 6 реальных скачиваний PDF/XLSX.
  Рабочая команда: 81 проверка; достижения помощи: 51.
- В Linux CI отдельно запускается новый PostgreSQL-набор границ сроков,
  включая истечение во время ожидания блокировки.
- Пять Linux-проверок резервного копирования и установки cron успешно
  выполнены на изолированных фикстурах. Синтетический PostgreSQL-дамп
  восстановлен в отдельный контейнер без сети: две таблицы, две вымышленные
  учётные записи, две заявки, внешний ключ проверен реальной ошибочной вставкой.
  Контейнер удалён; рабочий дамп при этой проверке не создавался.

Ошибки фикстур исправлялись под действующие правила продукта. Тарифы и рабочие
потоки для получения зелёного теста не менялись. Новый общий запуск всех
браузерных проверок: `python tests/run_browser_qa.py --workers 2`.

## Состояние сервера и границы проверки

При чтении состояния VPS контейнеры app/db здоровы, bot/caddy работают.
Занято 23% диска, доступно около 2,8 ГБ памяти. Публично слушаются 22/80/443;
PostgreSQL и 8080 наружу не опубликованы. Это снимок состояния, не нагрузочный
тест или доказательство работы при массовом трафике.
Почтовая доставка сконфигурирована; бонус новых регистраций — 10 000 тестовых ₽.

Проверки изменений и синтетические регистрации выполняются на отдельных
временных базах. Опубликованный интерфейс проверяется без регистрации,
переписки и покупок в рабочей базе. Email-доставка в интеграционных тестах
перехватывается локально; реальные сообщения пользователям не рассылаются.
Telegram бизнес-логика проверяется fake Bot, а polling — по состоянию сервера.

После отдельного явного разрешения пользователя включены почасовые копии полной
базы в закрытую папку на VPS, хранение — 14 дней. Восстановление одного архива
проверено в отдельном PostgreSQL без сети: 69 таблиц, 114 внешних ключей,
невалидированных ключей нет. Временный контейнер удалён. Подробности:
[BACKUP_VERIFICATION_20261104.md](BACKUP_VERIFICATION_20261104.md).
Копии находятся на том же VPS; независимое внешнее хранилище ещё не настроено.

Результаты CI и проверки опубликованной версии фиксируются с точным SHA при
выкладке. Полная речь: [DEMO_DAY_SPEECH.md](DEMO_DAY_SPEECH.md).
Ближайшее развитие: [DEVELOPMENT_ROADMAP.md](DEVELOPMENT_ROADMAP.md).

## Что осталось сделать самому перед выходом

1. Уточнить длительность и критерии организаторов, прочитать речь с таймером.
2. Открыть два профиля браузера с локальным демо и заранее скачать смету.
3. Сохранить короткую запись показа и слайды для отсутствия интернета.
4. Назвать только фактические результаты реального пилота. Тестовые деньги
   и демонстрационные аккаунты не являются продажами и спросом.
5. Зафиксировать проверенную версию; новую функцию перед выходом добавлять
   только при необходимости и с повторной проверкой её сценария.
